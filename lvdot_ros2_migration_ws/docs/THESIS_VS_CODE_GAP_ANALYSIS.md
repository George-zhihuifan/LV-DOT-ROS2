## 2. "必须补"的几项详解

### 2.1 关联匹配代价（#2）

**论文公式 (42)**：
```
C_ij = λ_d · d_Maha(预测位置, 检测) + λ_iou · (1 - IoU_3D(预测框, 检测框))
```

**当前实现**：`feature_weight = [3.0, 3.0, 0.1, 0.5, 0.5, 0.05, 0.0, 0.0, 0.0]` 走基线的特征向量相似度。

**为什么必须补**：
- 论文 §1.3.5 倒数第三段原话："**区别于基线框架采用特征向量相似度结合 IoU 阈值的贪心匹配**" —— 但代码里现在就是基线
- 这是答辩时被问"你这跟原 LV-DOT 有啥区别"的关键差异点之一

**补的位置**：`lvdot_ros2_migration_ws/src/lvdot_ros2/src/lvdot_detector_node.cpp` 或关联子模块（C++）。需要：
1. 从 KF 拿到预测协方差 `P_t|t-1`（位置维度）
2. 计算每对（track, detection）的马氏距离
3. 算 IoU_3D（AABB 简化版即可）
4. 组合代价并送给匈牙利

**工作量**：中等（C++ 代码改动 + 重新调 λ_d, λ_iou, 门限 C_gate 三个超参数）。

### 2.2 三级抖动抑制（#3.1 / 3.2 / 3.3）

这是论文 §1.1 列出的**三大改进之一**（另外两个是 QC-GAF 和 KF-GRU 混合预测），三层全都没实现。三层之间是协同关系（论文 §3 结尾段说明），缺一层就不能说"全链路抖动抑制"。

**§3.1 检测层 EMA**：最简单，加在 `lvdot_detector_main` 的 dynamic/tracked_bboxes 发布前；自适应 α（位移超阈值切高 α_high）。

**§3.2 融合层匹配迟滞**：在 `qcgaf_fusion_node` 内对软匹配矩阵 S 做 EMA + 双阈值 hysteresis（θ_enter / θ_exit）。

**§3.3 跟踪层 Q/R 自适应**：需要打通 `qcgaf_fusion_node → lvdot_detector_main` 的 quality 信号（新加一个 topic `/qcgaf/quality_vector`），然后 detector 内部按 H_c / H_l 算 `Q_k = Q_base · (1 + α_Q · (1 - max(H_c, H_l)))`。

**为什么必须补**：论文标题副标三个关键词之一就是"抖动抑制"。没这块论文只能写"两个改进"。

**工作量**：3.1 小、3.2 中、3.3 中（含 topic plumbing）。

### 2.3 GRU γ 自适应（#4）

**论文公式 (40)** 是 sigmoid 函数对比 KF 和 GRU 过去 W 帧的平均误差：
```
γ_t = 1 / (1 + exp(-β_s · (e_t^GRU - e_t^KF)))
```

**外加遮挡修正 (41)**：
```
γ_t *= max(0, 1 - c_occ(t) / C_max)
```

**当前实现**：HybridPredictor 内部按"近用 KF、远用 GRU"做时间步分段，**没有按错误对比，也没有按遮挡时长**。

**为什么必须补**：
- 论文 §1.3.4 把这个公式写得很具体，答辩时会被问"γ 是怎么算的"
- 当前的时间步分段在做"等速直线 + 突然转弯"的场景区分不出来——这正是论文要解决的非线性运动场景

**补的位置**：`gru_predictor/gru_predictor/src/hybrid_predictor.py`，加 W 帧 buffer + sigmoid + 遮挡 attenuation。

**工作量**：中（Python，但要小心数值稳定性）。

### 2.4 评估指标体系对齐（#7）

**论文 §4.2 要求**：
- Precision/Recall/F1 **at IoU 0.3 / 0.5 / 0.7**
- **MOTA / IDF1 / IDSW** / 轨迹保持率
- **ADE / FDE**
- 逐模块延时表

**当前**：只有 center distance（2.5m gate）+ 简化 MOTA。其他全没。

**为什么必须补**：
- 没这些指标论文实验章节就只能写当前这点东西，分量不够
- 消融实验（论文 §4.3）依赖这套评估指标做 A-G 7 个配置的横评

**怎么补**：
1. 改 `detection_evaluator.py`：
   - 加 3D IoU 匹配模式（GT 用 0.5×0.5×1.7m 默认人形 box）
   - 报 IoU 0.3 / 0.5 / 0.7 三档的 P/R/F1
   - 加 IDF1 / IDSW（每帧维护 gt_id → matched_track_id 映射，记 switch 次数）
2. 新写 `prediction_evaluator.py`：
   - 订 `/gru_predictor/predicted_positions` + `/pedestrian_sim/agent_states`
   - 滚动窗口缓存 GT，按预测时间步对比 GT 在 T+i·dt 的位置
   - 算 ADE / FDE / Miss Rate

**工作量**：中（纯 Python，关键是 IDF1/IDSW 的 ID 对齐逻辑要细心）。

### 2.5 消融实验设计（#8）

依赖 #7 跑通才能做。论文 §4.3 表格里 A-G 7 个配置：

| | 自适应融合 | 抖动抑制 | GRU 混合 |
|---|---|---|---|
| A | × | × | × |
| B | √ | × | × |
| C | × | √ | × |
| D | × | × | √ |
| E | √ | √ | × |
| F | √ | × | √ |
| G | √ | √ | √ |

**怎么补**：launch 文件加 3 个开关：
- `enable_qcgaf:=true/false`（false 时走规则融合：纯 IoU 匹配 + 取并集）
- `enable_jitter_suppression:=true/false`
- `enable_gru:=true/false`（false 时纯 KF）

每个配置跑一次 60 秒 sim，写 CSV 汇总。

**工作量**：中（每个开关都要落到对应代码里有真的退化路径）。

## 3. "可选补"的（不补也无所谓）

### 3.1 动态分类语义条件（#6）

论文 §1.3.6 公式：dynamic = (YOLO 类 ∈ {行人/车/骑行}) **OR** (KF 速度 > 阈值)。

当前只有后半个条件。补法简单：在 detector 内部把 `yolo_human` 标记带到 track 上，分类时 OR 进去。

不补的影响：静止行人（等红灯）会被分类成静态。但 sim 里行人全在动，不会触发这个 case。所以仿真评估不受影响，但答辩可能被问。

**建议**：等评估体系跑通有时间再补；如果论文里要写"语义+运动双条件"就**必补**。

## 4. "不必要补"的

### 4.1 KF 状态加速度项（#1）

论文写 9 维（常加速度模型），实际 7 维（常速度 + size）。

**为什么不补**：
- 30Hz 帧率下，0.3-1.5 m/s² 的人/车加速度对位置预测的二阶项 = 0.5 · 1.5 · (1/30)² ≈ 0.8 mm/帧，远小于检测噪声（数十厘米）
- 加上加速度反而让 KF 在突然转向时出现预测过冲
- 学界很多跟踪器（SORT、OC-SORT）都用常速度

**论文怎么改**：把 §1.3.2 公式 (29) 改回 6 维 + size 维度即可。这是合理的工程简化。

### 4.2 YOLO 框拆分（#5）

论文 §1.2.2 第三段写的"一融合框对应多 YOLO 框 → 拆分"。

**为什么不补**：
- 当前场景行人间距 ≥1m，融合框聚类很少把多人合一
- 实际 sim 跑下来这种情况几乎不发生（log 里 `mutual` 计数能看出来）
- 补这个的工程复杂度（要做 2D YOLO 框到 3D 融合框的一对多投影 + 拆分逻辑）跟收益不成比例

**论文怎么处理**：可以保留 §1.2.2 这段文字描述（说明设计意图），实验里说"未观测到需要拆分的场景"。

### 4.3 训练数据策略（#9）

论文 §2.5 说要在 Gazebo + KITTI 上注入退化训练 QC-GAF。实际 GRU 用 nuScenes 训的。

**为什么不补**：
- 重训成本高（几小时到几天的 GPU 时间）
- 现有模型在 sim 上已经能 inference 出 fused box
- 论文里把数据来源改写成"nuScenes + Gazebo 退化场景"即可

### 4.4 ROS 版本（#10）

**不动**。ROS 2 Humble 比 Noetic 先进，论文里直接改版本号说"基于 ROS 2 Humble"即可。

## 5. 推荐的补实现顺序

按"先建评估闭环、再做算法改进"的逻辑：

```
Phase 1 (一周内): 把评估闭环搭起来——所有后续改动才能量化
  └─ #7  评估指标对齐 (3D IoU + IDF1 + IDSW + ADE/FDE)
  └─ #8  消融实验 launch 开关

Phase 2 (一周内): 论文核心算法改进
  └─ #2  关联匹配代价 (马氏距离 + 3D IoU)         ← C++ 中改动
  └─ #4  GRU γ 自适应 (三因素)                     ← Python 中改动
  └─ #6  动态分类语义条件 (可选)                   ← C++ 小改动

Phase 3 (一到两周): 三级抖动抑制
  └─ #3.1 检测层 EMA 平滑
  └─ #3.2 融合层匹配迟滞 (需要 QC 输出 quality topic)
  └─ #3.3 跟踪层 Q/R 自适应 (依赖 #3.2 的 quality topic)
       └─ 注: 3.3 在跑通 QC quality → KF 通信后再做最佳

Phase 4: 跑完整消融实验 A-G 7 个配置，产出最终评估表
```

**总工作量估算**：3-5 周（含调参 + sim 跑数据）。如果只补 Phase 1 + Phase 2，2 周可以拿到答辩需要的数字。

## 7. 一句话总结

**当前代码 vs 论文，QC-GAF 那块（论文第 2 章）做得最完整；KF-GRU 混合预测（§1.3.4）和抖动抑制（§3）都是论文卖点但代码里要么简化、要么完全没有；评估指标体系（§4.2）也基本没建。**

**优先做的事**：先把评估闭环（#7+#8）和评估指标补齐，**有了量化的尺子再补算法**。否则补完了不知道好没好。
